# Объекты и задачи

Мини-CRM для строительной компании. Постановщик управляет объектами и задачами, исполнитель работает со своими задачами и сдаёт их на проверку.

## Запуск

Требуется Node.js 20.19+ или 22.12+.

```bash
npm ci
cp .env.example .env.local
npm run dev
```

В `.env.local` задайте `VITE_SUPABASE_URL` и `VITE_SUPABASE_PUBLISHABLE_KEY` отдельного проекта Supabase. Клиент использует публичный ключ. Ключи `service_role`, секретные ключи и пароли хранятся отдельно от проекта.

## Supabase

1. Примените SQL-миграции из `supabase/migrations` в порядке имён файлов. Для отдельного, уже привязанного Supabase CLI проекта используйте `supabase db push`.
2. В разделе **Authentication → Sign In / Providers** отключите **Allow new users to sign up**. Проверьте, что `/auth/v1/settings` с публичным ключом возвращает `disable_signup: true`.
3. Добавьте пользователей с подтверждённым email в **Authentication → Users**. Для каждого создайте профиль с UUID этого пользователя, именем и ролью.

```sql
insert into public.profiles (id, display_name, role)
values ('<uuid пользователя>', 'Имя в CRM', 'manager');
```

Используйте `manager` для постановщика и `worker` для исполнителя. Для проверки создайте двух пользователей каждой роли. Доступ к демо-аккаунтам передаётся отдельно.

## Цикл задачи

| Действие | Кто выполняет | Статус после действия |
| --- | --- | --- |
| Создать задачу | Постановщик | Новая |
| Взять новую задачу или начать доработку | Назначенный исполнитель | В работе |
| Отправить на проверку | Назначенный исполнитель | На проверке |
| Вернуть с обязательным комментарием | Постановщик | На доработке |
| Принять | Постановщик | Принята |

RLS ограничивает чтение задач, объектов и истории. PostgreSQL проверяет переход в RPC, блокирует строку задачи на время операции и записывает историю в той же транзакции. Прямое изменение статуса, автора и времени создания, а также запись в историю запрещены правами таблиц. При мягком удалении задачи или объекта записи истории остаются в базе.

## Проверка

```bash
npm run typecheck
npm run build
```

- Под первым постановщиком создайте общий объект с отдельной задачей для каждого исполнителя и ещё один объект с задачей только для второго исполнителя.
- Проверьте под обоими исполнителями списки, фильтры и прямые ссылки на чужие задачи. Первый исполнитель должен видеть на общем объекте только свою задачу, а закрытый объект должен быть доступен только второму.
- Проведите задачу через проверку, возврат с комментарием, доработку и принятие вторым постановщиком. Сверьте участников, время, переходы и комментарий в истории.
- Повторите запросы под сессиями обеих ролей через Supabase Data API. Чтение чужой задачи и истории должно возвращать пустой список. Прямой `PATCH` статуса и изменения истории должны завершаться ошибкой. Из двух одновременных одинаковых переходов должен пройти один.
- Проверьте мягкое удаление задачи и объекта. Удалённые записи исчезают из интерфейса, история сохраняется в базе.

## Vercel

Для публикации импортируйте репозиторий в отдельный проект с пресетом Vite. Добавьте обе переменные окружения из `.env.example`. Настройка `vercel.json` направляет маршруты React Router в `index.html`, поэтому прямые ссылки на карточки работают при обновлении страницы.
